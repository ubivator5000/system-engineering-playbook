6. System Requirements

1. Платежи и идемпотентность

SYS-01: Система должна отклонять запрос на создание платежа с уже использованным Idempotency-Key для той же школы, возвращая HTTP 409 Conflict и ранее созданный объект платежа.

SYS-02: Система должна хранить использованные Idempotency-Key не менее 30 дней с момента создания платежа.

SYS-03: Система должна обеспечивать уникальность поля order_id в пределах одной школы на уровне базы данных (UNIQUE constraint).

SYS-04: При создании рекуррентного платежа система должна сохранять связь между родительским платежом и всеми дочерними (повторными) списаниями.

2. Интеграции с внешними системами

SYS-05: Система должна предоставлять WordPress-плагин, устанавливаемый из официального каталога WordPress без ручной загрузки файлов.

SYS-06: Система должна принимать от WordPress и Tilda HTTP-запросы с параметрами: amount, product_name, product_id, student_name, student_surname, student_phone.

SYS-07: Система должна отправлять вебхук в Битрикс24 при каждом успешном платеже для создания сделки и задачи менеджеру.

SYS-08: Система должна предоставлять внешнюю обработку (файл .epf) для 1С:Бухгалтерии, доступную для скачивания из личного кабинета.

SYS-09: Система должна поддерживать эндпоинт GET /api/v1/payments для выгрузки списка платежей в 1С с фильтрацией по дате и школе.

3. Retry-механизм и отказоустойчивость

SYS-10: Система должна автоматически выполнять повторные попытки списания при отказе платежа с интервалами: 1 час, 24 часа, 72 часа (всего 3 попытки).

SYS-11: Система должна прекращать дальнейшие retry-попытки после успешного списания.

SYS-12: Система должна отправлять уведомление менеджеру в мессенджер после третьей неуспешной попытки списания.

SYS-13: Система должна поддерживать настраиваемое количество retry-попыток (от 0 до 5) через личный кабинет школы.

SYS-14: При недоступности банка-эквайера система должна возвращать ошибку 503 Service Unavailable и не инициировать списание.

4. Уведомления

SYS-15: Система должна отправлять уведомление менеджеру в ВК (через API VK) не позднее 10 секунд после успешного платежа.

SYS-16: Тело уведомления менеджеру должно содержать: ФИО студента, телефон, название курса и сумму платежа.

SYS-17: Система должна отправлять студенту напоминание о предстоящем списании за 3 дня до даты автоплатежа (через СМС или ВК).

SYS-18: При недоступности сервиса уведомлений (ВК, СМС-провайдер) система должна логировать ошибку и не блокировать основной платёжный процесс.

5. Безопасность

SYS-19: Система не должна принимать, хранить или передавать данные банковских карт (PAN, CVV, срок действия) — все платёжные данные направляются напрямую на страницу банка-эквайера.

SYS-20: Все API-эндпоинты должны быть доступны только по HTTPS с TLS версии 1.2 или выше.

SYS-21: Каждый запрос к API PayLect должен содержать подпись HMAC-SHA256, сформированную с использованием Secret Key школы.

SYS-22: Система должна отклонять запросы с подписью, сформированной более 5 минут назад (проверка timestamp).

SYS-23: Система должна ограничивать количество запросов с одного IP до 5 запросов в минуту (rate limiting).

6. Аналитика и отчётность

SYS-24: Система должна предоставлять владельцу школы дашборд с метриками: общая выручка, количество оплат, LTV (средний чек × количество платежей на студента), отток (доля студентов, прекративших оплату) — отдельно по каждому курсу.

SYS-25: Система должна позволять экспорт отчёта по платежам за выбранный период в формате CSV или JSON.
