| Поле | Значение |
|------|----------|
| **ID** | TC-001 |
| **Название** | Уведомление менеджера в ВК после успешной оплаты |
| **Связанные требования** | SR-01, SR-02, SYS-15, SYS-16 |
| **Предусловия** | 1. Школа зарегистрирована в PayLect<br>2. В личном кабинете указан номер телефона менеджера в ВК<br>3. WordPress-виджет настроен и вставлен на страницу курса |
| **Шаги** | 1. Студент открывает страницу курса<br>2. Нажимает «Оплатить»<br>3. Вводит ФИО и телефон<br>4. Вводит данные карты на странице Т-Банка<br>5. Подтверждает платёж |
| **Ожидаемый результат** | 1. Платёж успешно проведён<br>2. Студент получил подтверждение<br>3. Менеджер получил сообщение в ВК < 10 секунд<br>4. В сообщении указаны: ФИО студента, телефон, название курса, сумма |

### ТК-02. Автоматический retry при отказе карты

| Поле | Значение |
|------|----------|
| **ID** | TC-002 |
| **Название** | Retry-механизм при временном отказе карты |
| **Связанные требования** | SR-03, SYS-10, SYS-11, SYS-13 |
| **Предусловия** | 1. Оформлена подписка на курс<br>2. У студента есть карта с лимитом, которого хватает только на 2-ю попытку<br>3. В настройках школы установлено 3 retry-попытки |
| **Шаги** | 1. Наступает дата планового списания<br>2. Система пытается списать → отказ (недостаточно средств)<br>3. Ожидание 1 час → вторая попытка → отказ<br>4. Ожидание 24 часа → третья попытка → успех |
| **Ожидаемый результат** | 1. После первого отказа система не отправляет уведомление менеджеру<br>2. После успешной попытки списание зафиксировано<br>3. Дальнейшие retry-попытки не выполняются |
| **Пост-условия** | В логах аудита зафиксированы все 3 попытки с status: `failed` → `failed` → `succeeded` |
| **Окружение** | Тестовая среда PayLect с симулятором Т-Банка |

### ТК-08. Идемпотентность платежа

| Поле | Значение |
|------|----------|
| **ID** | TC-008 |
| **Название** | Повторный запрос с одинаковым Idempotency-Key не создаёт дубль |
| **Связанные требования** | SYS-01, SYS-02, NFR-02 |
| **Предусловия** | 1. PayLect API доступен<br>2. Сгенерирован уникальный Idempotency-Key = `uuid-123` |
| **Шаги** | 1. Отправить POST /api/v1/payment с Idempotency-Key: uuid-123 → успех, payment_id = P1<br>2. Тут же отправить второй такой же запрос с Idempotency-Key: uuid-123 |
| **Ожидаемый результат** | 1. Второй запрос вернул HTTP 409 Conflict<br>2. Тело ответа содержит payment_id = P1 (тот же, что в первом запросе)<br>3. В БД создан только один платёж (нет дубля) |
| **Пост-условия** | Через 31 день ключ удаляется, новый запрос с тем же ключом создаст платёж |
| **Окружение** | Тестовый API PayLect |
